# Conv Paper Hyperparameter Protocol

Updated: 2026-07-03

This protocol defines how to choose solver settling/unroll counts (`T` and `K`), hard-sigmoid operating point, `input_gain`, learning rate, and epoch budget for Conv DRN amplification paper runs. The goal is to avoid choosing settings that favor one amplification case by accident while still allowing each nonlinearity to use a physically sensible operating range.

## Fixed Comparison Axes

These must be fixed inside each final comparison table:

- Architecture: Conv depth, channel counts, kernel, stride, padding, output dimension.
- Dataset preprocessing: MNIST mean, std, scale, and signed-input convention.
- Nonlinearity family: `hard_sigmoid` or `perfect_diode`.
- Amplification grid: `v1/c1`, `v2/c1`, `v4/c1`, `v1/c2`, `v1/c4`.
- Seed list for final paper runs.
- Batch size.
- Epoch budget.
- Checkpoint rule for downstream analysis: use `best_model.pt` unless explicitly studying final-epoch behavior.

For hard-sigmoid comparisons, these must also be fixed inside the main comparison table:

- `v_off`.
- Target initial saturation.

Current paper-facing default:

- `v_off=4.0`.
- `50%` target initial saturation for the main matched-operating-point comparison.
- Keep `70%` and other saturation points as sweep/control runs, not as replacements for the main fixed-50 comparison unless the paper explicitly reports a tuned upper envelope.

Settings that may differ between nonlinearity families:

- `input_gain`.
- Solver settling/unroll counts: free-state inference iterations `T` and BP/EP unroll iterations `K`.
- Learning-rate grid, if the nonlinearity has clearly different gradient scale.

Settings that may differ between amplification schemes only after a documented sweep:

- Learning rate.
- For hard sigmoid, raw `input_gain` may differ between amplification settings only when it is generated by the same deterministic calibration rule to hit a fixed target initial saturation. This is operating-point matching, not accuracy tuning.

Settings that should not differ between amplification schemes in the final paper run:

- Hard-sigmoid `v_off` and target initial saturation.
- `T` and `K`.
- Epoch budget.
- Preprocessing.
- Architecture.

For hard sigmoid, do not use same-raw-`input_gain` results as the main accuracy comparison. Same-raw-`input_gain` runs are diagnostics for showing how amplification shifts the operating point.

## Stage 1: Choose Solver Settling And Unroll Counts

Choose `T` and `K` before choosing the hard-sigmoid operating point, perfect-diode `input_gain`, or LR.

Here `T` is the number of free-state inference/settling iterations used before measuring loss gradients, and `K` is the number of BP/EP unroll or nudged-phase iterations used for the gradient estimate. Do not infer the `K` requirement from a sweep that ties `T=K`; tied sweeps confound settling and gradient-tail length. For `T/K` diagnostics, disable adaptive equilibrium stopping so requested counts are exact. Adaptive early stopping from an already-settled free state can stop after one odd/even sweep and make upstream conv gradients look exactly zero even when fixed-step BP and zero-order finite differences are nonzero.

Simulator/minimizer settings must be explicit in every paper-facing source config. Do not rely on Python defaults for updater choice, adaptive stopping, tolerances, Newton/polish settings, clipping, overrelaxation, or experimental IV settings. For fixed-`T/K` BP/EP paper runs, `model_base.minimizer.adaptive_equilibrium` must be `false`; adaptive-equilibrium runs are diagnostics unless the table explicitly studies adaptive stopping.

Required `model_base.minimizer` fields:

- `double_diode_updater`, `single_diode_updater`, `adaptive_equilibrium`, `overrelaxation_factor`;
- `iv_data_path`, `experimental_damping`, `experimental_newton_max_steps`;
- `settings.rel_tol`, `settings.vn_tol`, `settings.use_polish`, `settings.max_newton_iters`, `settings.z_thresh`, `settings.exp_clip`, `settings.dynamic_polish`;
- `settings.overrelaxation_reject_steps`, `settings.overrelaxation_reject_max_tries`, `settings.overrelaxation_reject_shrink`, `settings.overrelaxation_reject_eps`;
- `settings.experimental_exponential_newton_tol_progressive`, `settings.experimental_exponential_newton_tol_start`, `settings.experimental_exponential_newton_tol_end`, `settings.experimental_exponential_newton_tol_switch_hi`, `settings.experimental_exponential_newton_tol_switch_lo`.

For hard sigmoid:

1. Measure raw residual current `max |dE/dz|` versus `T`.
2. Measure centered-EP versus BP cosine similarity on a grid of `T` and `K`.
3. Measure per-parameter gradient norms and zero fractions on the same `T/K` grid, especially `ConvWeight_0`, `ConvWeight_1`, and any deeper conv weights. For conv layers, these are shared-kernel parameter gradients after summing over spatial uses of the same kernel entry; if spatial-copy behavior is in question, also record pre-reduction per-location contribution statistics.
4. Check whether early-conv gradients survive at the selected `T`. Do not transfer `T/K` thresholds from another nonlinearity family without rerunning this diagnostic for hard sigmoid.
5. Use the same `T` and `K` for all amplification settings within a given architecture and nonlinearity unless one setting is clearly non-convergent or gradient-dead and must be analyzed separately.

For perfect diode:

1. Use projected KKT residuals for clamped diode variables.
2. Use raw residuals only for unconstrained layers.
3. Also run the centered-EP versus BP cosine diagnostic, because projected residual alone does not guarantee useful training gradients.
4. Check whether early-conv gradients survive at the selected `T`, using the same separate fixed-iteration `T/K` diagnostic as hard sigmoid. Record whether adaptive equilibrium was disabled; adaptive-stop rows are diagnostics for solver stopping behavior, not evidence that fixed-step gradients are dead.

Default `T/K` selection rule:

- Before launching a final training run, run a fixed-iteration residual-vs-K gate for the exact architecture, nonlinearity, operating point, and preprocessing that will be trained.
- The K grid must include the intended training K and at least two larger sentinel values, for example `K`, `2K`, and `4K`; if the residual is still dropping at the largest sentinel, extend the grid before launching.
- Disable adaptive early stopping for this gate, or record actual iterations used and treat early stopping itself as the convergence evidence. Do not infer a high-K plateau from an adaptive run that stopped early without reporting the residual trend.
- Judge hard-sigmoid and other smooth/clipped runs with raw residual current. Judge perfect-diode hidden layers with projected KKT residuals, while still recording raw residuals so boundary multiplier current is visible.
- Treat K as high enough only when the relevant per-layer and aggregate residual curves have stagnated: the next larger tested K changes the residual by no more than `20%` relative, or the residual is already below the run's numerical floor. If the curve is monotone decreasing by more than this threshold, increase K or label the run preliminary.
- Also record the per-layer voltage update size versus K. A small voltage update is useful supporting evidence, but it does not replace the residual-stagnation requirement.
- For trainable nonlinearity parameters, especially hard-sigmoid `trainable_v_off`, run this gate after checkpoint reload for resumed/final checkpoints and verify that residual interactions read the loaded parameter values rather than cached initialization-time bounds.
- Use beta `0.25` as the primary EP/BP diagnostic curve.
- Select the smallest `T` whose residual curve has stagnated enough for the intended protocol and whose upstream gradients are still useful.
- After `T` is fixed, select the smallest `K` whose all-parameter cosine is within `0.01` absolute cosine of the best tested `K` at that `T`.
- Launch final training only when both the residual-stagnation gate and the EP/BP cosine rule pass.
- If increasing `T` kills early-conv gradients, label lower-`T` nonzero gradients as transient unless the paper explicitly studies a transient-gradient protocol.
- If the residual curve is still visibly decreasing at the selected `T`, pick the larger `T` or label the run as preliminary.
- Record the `T/K` grid, selected `T`, selected `K`, residual mode, residual-stagnation decision, whether adaptive equilibrium was disabled, residuals, EP/BP cosine curve, and per-parameter gradient zero fractions in the result directory config and summary.

## Stage 2: Choose Operating Point And Input Gain

For hard sigmoid, choose one operating point per architecture and nonlinearity, then derive the raw `input_gain` needed for each amplification setting by a documented calibration rule.

Do not tune raw `input_gain` separately per amplification setting using accuracy. That would make the amplification comparison hard to interpret.

Main hard-sigmoid comparison:

1. Fix `v_off`.
2. Fix target initial saturation.
3. Use the same deterministic input-gain calibration procedure for every amplification setting.
4. Record the calibrated raw `input_gain` for every run.
5. Treat per-amplification raw `input_gain` differences as operating-point calibration, not as a tuned hyperparameter.

Diagnostic hard-sigmoid comparison:

- Same-raw-`input_gain` runs may be reported only as diagnostics.
- They are useful for showing how voltage/current amplification changes saturation and operating regime.
- They should not be the primary clean-accuracy evidence.

Tuned hard-sigmoid upper-envelope comparison:

- A per-amplification saturation/LR sweep may be reported separately as a tuned upper envelope.
- Do not mix tuned-envelope rows with matched-operating-point rows in the same main table unless the distinction is explicit.

The allowed granularity is:

```text
Conv1 hard_sigmoid: one shared v_off and target saturation; calibrated input_gain per amp if needed
Conv1 perfect_diode: one shared input_gain for all amps
Conv2 hard_sigmoid: one shared v_off and target saturation; calibrated input_gain per amp if needed
Conv2 perfect_diode: one shared input_gain for all amps
Conv3 hard_sigmoid: one shared v_off and target saturation; calibrated input_gain per amp if needed
Conv3 perfect_diode: one shared input_gain for all amps
```

It is acceptable for hard sigmoid and perfect diode to use different input-drive rules, because hard sigmoid has a finite active window while perfect diode has a different clamping/conduction mechanism. It is also acceptable for Conv1, Conv2, and Conv3 to use different operating points or `input_gain`, because the input drive is filtered by different architectures.

Hard-sigmoid operating-point sweep:

1. Use seed `0` first.
2. Use the `T` and `K` selected in Stage 1.
3. Fix architecture, nonlinearity, preprocessing, batch size, initialization, and epoch budget.
4. Run each candidate target saturation on all five amplification settings:

```text
v1/c1, v2/c1, v4/c1, v1/c2, v1/c4
```

5. Use exactly `10` epochs for the operating-point screen unless the run is explicitly labeled as a longer LR check or final run.
6. Record the calibrated raw `input_gain` for each amplification setting.
7. Record saturation statistics for each dynamic layer:
   - fraction below `v_min`;
   - fraction inside `[v_min, v_max]`;
   - fraction above `v_max`;
   - outside-window fraction;
   - p10, p50, p90 states.
8. Record EP/BP cosine and per-parameter gradient zero fractions at the same `T/K`.
9. Record best and final test accuracy, final train/test loss, and whether train loss is still decreasing.

Perfect-diode input-gain sweep:

1. Use seed `0` first.
2. Use the `T` and `K` selected in Stage 1.
3. Fix architecture, nonlinearity, preprocessing, batch size, initialization, and epoch budget.
4. Run every candidate `input_gain` on all five amplification settings.
5. Use exactly `10` epochs for the input-gain screen.
6. Record EP/BP cosine and per-parameter gradient zero fractions at the same `T/K`.
7. Record best and final test accuracy, final train/test loss, and whether train loss is still decreasing.

Learning-rate compensation during operating-point/input-gain screens:

- A fixed-LR-only screen is allowed as a coarse screen, but it is not sufficient to freeze the paper setting if the losses are still decreasing.
- For a fairer screen, use a reference LR and scale it with raw input gain:

```text
lr(G) = lr_ref * G / G_ref
```

- If runtime allows, evaluate a small local LR neighborhood around the scaled value:

```text
0.5 * lr(G), 1.0 * lr(G), 2.0 * lr(G)
```

Example:

```text
If input_gain=10 uses lr=0.0001,
then input_gain=20 should test around lr=0.0002,
and input_gain=40 should test around lr=0.0004.
```

Hard-sigmoid operating-point selection rule:

1. Reject operating points with collapsed or non-finite runs.
2. Reject operating points where any amplification setting fails to learn at all unless neighboring LRs also fail.
3. Prefer a matched operating point that is interpretable across all five amplification settings, not simply the highest single-row accuracy.
4. Current default for the main hard-sigmoid comparison is fixed `v_off=4.0` and `50%` target initial saturation.
5. Use saturation and EP/BP cosine as guardrails:
   - avoid operating points where the first dynamic layer is almost entirely outside the active window and ConvWeight_0 EP/BP cosine is poor;
   - if a lower-saturation or lower-drive setting improves cosine but substantially hurts clean accuracy, keep the higher-accuracy setting and document the tradeoff.
6. If two operating points are statistically or practically tied, choose the lower-saturation operating point for the main matched comparison and keep the higher-saturation point as an appendix/control.

The chosen hard-sigmoid operating point is then frozen before the LR sweep. The LR sweep may choose different LRs for different amplification settings, but it must not change `v_off`, target saturation, or the input-gain calibration rule.

Perfect-diode input-gain selection rule:

1. Reject gains with collapsed or non-finite runs.
2. Reject gains where any amplification setting fails to learn at all unless neighboring LRs also fail.
3. Prefer the gain with the best mean best-test accuracy across the five amplification settings.
4. Use EP/BP cosine as a guardrail.
5. If two gains are statistically or practically tied, choose the lower gain.

The chosen perfect-diode `input_gain` is then frozen before the LR sweep. The LR sweep may choose different LRs for different amplification settings, but it must not change `input_gain`.

## Stage 3: Choose Learning Rate

After `T/K` and the operating-point/input-gain choice are fixed, choose LR.

The LR protocol is seed-0 only. Multiple seeds are reserved for the final frozen paper run, after `T/K`, hard-sigmoid operating point or perfect-diode `input_gain`, LR, and epoch budget have been selected.

Allowed LR granularity:

```text
preferred: one LR per architecture + nonlinearity + amplification setting
allowed: one shared LR per architecture + nonlinearity, if it trains all amps well
not allowed: changing LR across seeds for the same final configuration
```

Using a per-amplification LR is acceptable because amplification changes gradient scale and convergence speed. The important constraint is that every LR is chosen by the same documented rule, not hand-picked after seeing final paper results.

### Stage 3a: Seed-0 LR Screen

1. Use the selected `T/K` and the frozen operating-point/input-gain choice.
2. Use seed `0`.
3. Run all five amplification settings.
4. Start from a broad LR grid informed by previous runs.
5. Use the same grid family across amplification settings, but allow shifted ranges when prior diagnostics show clear scale differences.
6. Use exactly `10` epochs.
7. Record best accuracy, final accuracy, train/test loss, best epoch, and whether loss is still decreasing.

The seed-0 screen proposes LR candidates. It does not use multiple seeds.

### Stage 3b: Seed-0 Long LR Check

Take the best one or two LR candidates per amplification setting from Stage 3a and rerun them with seed `0` for exactly `50` epochs.

This long seed-0 check decides whether the LR is good enough for the final paper run. It is especially important for ambiguous or undertrained cases:

- best epoch near the end of training;
- large gap between best and final accuracy;
- train loss still decreasing;
- high seed-0 sensitivity in earlier experiments;
- current-amplified settings such as `v1/c2` and `v1/c4`.

If the best LR from Stage 3a is still epoch-limited after `50` epochs, either select a higher-LR probe and rerun the `50`-epoch seed-0 check, or mark the configuration as requiring a longer final budget.

LR selection rule:

1. Discard non-finite or collapsed runs.
2. Primary criterion: highest best-test accuracy in the `50`-epoch seed-0 long check.
3. Tie-breaks:
   - lower final loss;
   - final accuracy close to best accuracy;
   - lower LR if still tied.
4. Prefer LRs whose final accuracy is close to best accuracy, because those runs are less sensitive to checkpoint timing.
5. Flag a run as epoch-limited if the best epoch is in the final `20%` of training or if train loss is still monotonically decreasing.
6. Flag a run as unstable if the best accuracy is good but final accuracy collapses or test loss increases sharply.
7. If the selected LR is epoch-limited for several amplification settings, extend the epoch budget or add a higher-LR probe before final paper runs.

Recommended LR grids:

- Start with logarithmic or semi-log grids, not a single hand-tuned value.
- For a narrow follow-up, use multiplicative neighborhoods around the current best:

```text
0.5 * lr_best, 0.75 * lr_best, 1.0 * lr_best, 1.5 * lr_best, 2.0 * lr_best
```

- If a run is stable and best epoch is late, add higher LR probes.
- If a run peaks early and degrades, add lower LR probes.
- If both low and high LRs fail, treat the issue as architectural, `T/K` convergence-related, or nonlinearity-related rather than only LR-related.

Paper reporting rule:

- Report the LR grid used to choose LRs.
- Report whether LRs are shared or per amplification.
- In the final table, include the selected LR for every amplification setting.
- State that LR selection was done on seed `0`, and that multiple seeds are used only in the final frozen run.

## Stage 4: Final Paper Training

Final paper runs should use:

- the selected architecture;
- selected nonlinearity-specific `T` and `K`;
- selected hard-sigmoid `v_off`, target initial saturation, and input-gain calibration rule, or selected perfect-diode `input_gain`;
- selected LR per amplification setting or a documented shared LR if it is adequate;
- seeds `0, 1, 2` at minimum;
- the same epoch budget for every amplification setting.

Epoch budget:

- Use the same number of epochs for all amplification settings in a table.
- Default final paper budget: exactly `50` epochs.
- Use exactly `100` epochs only if the `50`-epoch seed-0 LR check shows that several selected runs are still epoch-limited.
- Always report both best-checkpoint and final-epoch metrics.

## Daily Current-State Reporting

Each daily `docs/current_state.md` update for Conv hard-sigmoid runs should include a dated section (`YYYY-MM-DD`) with the tables below for Conv1 and Conv2 only, unless that day's update explicitly focuses on another architecture.

Calibrated saturation-target table:

- architecture;
- amplification scheme;
- target saturation;
- calibrated `input_gain`;
- LR or LR multiplier;
- best test accuracy;
- final test accuracy;
- best epoch;
- source result root.

Trained-network saturation table:

- architecture;
- amplification scheme;
- target saturation used for calibration;
- checkpoint measured, usually `best_model.pt` for best-accuracy rows and `final_model.pt` for final-epoch checks;
- evaluation split and sample count;
- per nonlinear-layer outside-window saturation at the trained checkpoint;
- max nonlinear-layer saturation;
- whether the final checkpoint differs materially from the best checkpoint.

Do not conflate target initial saturation with trained-checkpoint saturation. The target saturation documents the calibrated starting operating point; the trained-network saturation documents where the learned equilibrium states land after optimization.

Overall best-known table:

- architecture;
- amplification scheme;
- best known test accuracy;
- source protocol/root;
- comparability note.

The overall best-known table must label mixed raw-gain, saturation, `T/K`, LR, or epoch comparisons as `mixed protocol / diagnostic`. Mixed-protocol rows are useful for finding underperforming cases, but they are not main paper evidence.

Underperformance delta table:

- compute `overall_best - calibrated_best` in percentage points;
- flag rows with a gap greater than `1.0` percentage point;
- explicitly label mixed-protocol comparisons as diagnostic only;
- for rows with low absolute accuracy but no better historical row, mark the issue as absolute underperformance rather than a mixed-protocol gap.

## Paper Figure Inclusion Rule

Before choosing final paper figures, separate candidate runs into these buckets:

1. Main matched-operating-point hard-sigmoid comparison: fixed `v_off`, fixed target initial saturation, same `T/K`, same epoch budget, same LR-selection rule, final multi-seed runs.
2. Tuned hard-sigmoid upper-envelope comparison: best over saturation and LR per amplification, clearly labeled as tuned.
3. Same-raw-`input_gain` diagnostics: useful for operating-point-shift plots, not for the main clean-accuracy table.
4. Preliminary or excluded runs: single-seed screens, wrong-`T/K` runs, underconverged runs, or runs with inconsistent epoch budgets.

The main figures should prefer bucket 1. Bucket 2 can be an appendix/control if it helps show that conclusions are not an artifact of the fixed-50 operating point. Bucket 3 should only support the explanation of saturation shifts.
