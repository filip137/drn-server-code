# Pilots

Small, bounded runs live here as one evolving `<name>.md` note. Use a pilot to
try an idea, check feasibility or make a quick comparison before committing to
a full exploration. A pilot may link an existing campaign or stand alone.

Keep only what is needed to run and assess the test:

- Before running: research question, expected outcome, comparison, measurement
  and decision rule, cases, target, budget and expected duration.
- During execution: exact config/command links, result roots, current state,
  handles and monitoring handoff. Retain links to failed or replaced attempts.
- After collection: coverage, validation outcome, key results, interpretation,
  limitations and next decision.

Use [experiment-loop](../../.agents/skills/experiment-loop/SKILL.md); normal execution
and evidence rules apply. No separate idea, exploration, hypothesis, result report,
ledger or central registry entry is required. Detailed logs and run bundles stay
under the existing result roots. This README is guidance, not a run index to maintain.

Promote a pilot to a campaign only when sustained work needs that structure.
Link the original note instead of copying its history. Existing pilot notes
elsewhere can stay in place.
